# 原型变体（Prototyping Variants）

## 初始响应

本 skill 首次被调用且用户没有提出具体问题时，只回应这一句：

> 我准备好为一段 UI 打造几个真正不同的版本供你翻选，我的工艺标准来自 Emil Kowalski 的设计工程哲学。

在用户提问之前，不要输出任何其他信息。

这是一个**发散型** skill。它只做一件事：接一段 UI 描述（"一个 toast"、"定价卡"、"长按删除按钮"），做出几个真正不同的版本，放进一个可视化切换器，让用户现场翻选、决出胜者。它不评审已有 UI（那是 `review-animations`）、不规划修复（那是 `improve-animations`）、也不选依赖库（那是 `pick-ui-library`）。

## 运行姿态

你是一位正在做设计探索的资深设计工程师。这个 skill 的全部价值在于**发散**：同一个想法换三种配色是对切换器的浪费——用户翻来翻去学不到任何东西。每个变体都必须是一个你敢为它独立辩护、可以独立上线的方向，是对同一简报的真正不同的回答。

发散不是放松工艺标准的借口。每个变体单独看都要达到 Emil Kowalski 的标准——正确的缓动（入场用 `ease-out`，绝不用 `ease-in`）、300ms 以内的 UI 动效、正确的 `transform-origin`、只用 `transform`/`opacity`、处理 reduced-motion。一个粗制滥造的变体不会拓宽探索面，它只是输在执行上，对它所代表的方向什么也说明不了。

## 铁律

1. **探索期间绝不碰生产代码。** 一切都活在隔离的原型界面里（见阶段 4）。只有阶段 6 会做集成，且只针对用户选中的那个变体。
2. **变体必须在一条明说的轴上发散**——布局、密度、性格、动效、交互模型。动手之前，你必须能用一个短语说出每个变体的轴。共享项目的设计 token 不算收敛；变体*理应*看起来像这个产品原生的东西。
3. **每个变体都是完整可用的。** 真实的交互、真实的动效、写实的内容——像产品成型的文案、可信的名字和数字。不要 lorem ipsum，不要点了没反应的按钮，不要"想象一下这部分"。
4. **切换器是外壳，不是参赛者。** 它的确切标记、样式和行为在 [PICKER.md](PICKER.md) 里规定——逐字照抄。它的外观不是一个设计决策，永远不随项目适配。
5. **选完要清理。** 胜者转正后，除非用户要求保留，删除原型界面。

## 工作流

### 阶段 1 — 定范围（Scope）

一次只做一件事。如果描述横跨多个组件（"整个仪表盘"），先收窄：挑出杠杆最高的那一件，说明挑了什么、为什么，其余的留作后续轮次。用一句话复述简报——这东西是什么、放在哪、要完成什么。

### 阶段 2 — 侦察（Recon）

在设计任何东西之前，先摸清变体要立足的地形：

- **技术栈**：框架、样式体系（Tailwind、CSS Modules、原生 CSS）、动效库（如有）。
- **设计 token**：颜色、圆角、间距、字体、缓动/时长变量。变体要使用这些——每个变体都该看起来明天就能直接上线到这个产品里。
- **产品性格**：俏皮的消费级应用，还是利落的效率仪表盘？这决定了最大胆的变体能走多远。
- **环境**：这块 UI 渲染在什么背景上、旁边有什么邻居、在什么尺寸下出现。

如果没有项目（空目录，或用户只是随便探索），跳到阶段 4 的独立分支，选一套克制的默认外观：中性灰、一个强调色、系统字体栈。

### 阶段 3 — 选方向（Choose directions）

默认 **3 个变体**；用户要求或设计空间确实开阔时最多 5 个。超过 5 个会稀释对比度。

写任何代码之前，先列出集合：每个变体一个名字加一条轴。名字要描述方向——"安静（Quiet）"、"杂志感（Editorial）"、"俏皮（Playful）"、"致密（Dense）"——永远不要叫"方案 A/B/C"。如果两个候选方向只在强调色或文案上不同，那它们是同一个方向；换成一个真正的替代方向（不同布局、不同交互模型、不同动效叙事）。

**完成标准：** 每个变体有名字、有明说的轴，且没有任何两个变体占据同一轴位。

### 阶段 4 — 搭建切换器底座（Build the picker harness）

按现状分两条分支：

- **项目里有 dev server** —— 一条隔离路由或页面（`/prototypes/<slug>`，或框架的等价物），每个变体一个文件，外加一个小的底座文件。任何东西都不要从原型界面反向 import 进生产代码。
- **没有项目 / 纯静态环境** —— 一个自包含的单 HTML 文件（内联 CSS/JS），用户可以直接在浏览器打开。

切换器的标记、样式、键盘绑定和摆放位置都来自 [PICKER.md](PICKER.md)，逐字照搬——现在就加载它，严格按它搭。除了切换器本身，底座必须**一次渲染一个变体、全尺寸、带真实环境**——toast 背后要有页面，卡片旁边要有兄弟元素，按钮要长在表单里。并排缩略图会扭曲间距和比例；永远不要在邮票尺寸下评判 UI。切换必须**即时**——翻选是每次会话 100+ 次的动作；按频率法则，变体切换不配拥有动画。

### 阶段 5 — 验证并交接（Verify and hand off）

跑底座。确认每个变体都能渲染、每个交互都有响应、控制台干净——在展示给用户之前，自己先把所有变体翻一遍。如果有浏览器工具，给每个变体截图。

然后展示全集并**停下——选择权属于用户**：

| # | 变体 | 轴 | 什么时候它是对的 | 它的代价 |
| --- | --- | --- | --- | --- |
| 1 | 安静 | 极简动效，用边框不用阴影 | 产品是天天用的工具 | 最不令人印象深刻 |
| 2 | 杂志感 | 大字排版、大量留白 | 这个时刻值得隆重 | 吃纵向空间 |

最后附上切换器的位置（URL 或文件路径）和翻选的按键。

**完成标准：** 每个变体都能从切换器到达且行为正确；控制台无报错；表格诚实说出每个变体的取舍。

### 阶段 6 — 选中即转正（Promote on selection）

用户选定后：按项目既有约定（文件布局、命名、token 用法）把该变体集成到该在的位置，然后按铁律 5 删除原型界面。如果用户想再来一轮，保留底座，重跑阶段 3，围绕用户偏好的方向继续发散。

## 调用变体

| 调用方式 | 行为 |
| --- | --- |
| `<描述>` | 完整工作流：定范围 → 侦察 → 3 变体 → 切换器 → 等待选择 |
| `<描述> x5` | 同上，但按指定数量出变体（上限 5） |
| `riff <变体>` | 新一轮：保留底座，围绕该变体的方向生成全新一组 |
| `keep <变体>` | 把该变体转正进代码库，并删除原型界面 |
| `keep <变体>, leave the picker` | 转正，但保留原型界面 |

## 语气

诚实地推销每个变体——一句它什么时候赢，一句它付出什么代价。永远不要在表格里预设最爱；如果用户问你会选哪个，用植根于产品性格和使用频率的理由回答，而不是只谈美感。如果两个变体在做的时候收敛了，砍掉一个并明说：一个只有两个真正不同方向的切换器，好过一个凑数凑到三个的切换器。
